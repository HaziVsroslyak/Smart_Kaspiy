# Weather datasets

POST /api/v1/weather/datasets/import accepts JSON content containing an array of records, or CSV content with a header. Required columns: timestamp (timezone-aware ISO8601), latitude, longitude. Wind in m/s, wave height in metres; empty values remain null. Maximum 5 MiB and 20,000 rows. Duplicate coordinates/timestamps are rejected atomically. Uploaded source names/URLs are user declarations, marked uploaded_unverified and never fetched.

POST /api/v1/weather/datasets/fetch uses fixed Open-Meteo endpoints for archive or forecast, at most 31 days. Archives are reanalysis, not station observations or forecasts available at historical decision time. Actual grid coordinates, requested coordinates, retrieval time, source URL and SHA256 of normalized records are retained. Precipitation is a one-hour amount. No wave field is fabricated. Free hosted Open-Meteo usage is subject to its noncommercial terms: https://open-meteo.com/en/terms and https://open-meteo.com/en/docs/historical-weather-api .

GET /datasets and /datasets/{id} enforce account ownership (root may inspect). POST /datasets/{id}/resolve chooses nearest timestamp within 3 hours and position within 25 km; no temporal extrapolation. Missing wind/waves produces status missing with named gaps. These are selection tolerances, not an assertion of navigational safety.

A real 24-hour archive fetch for 2024-01-01 is included in contracts/examples/open_meteo_archive_real.json. Copernicus credentials, storm bulletin ingestion and AIS/port schedules are not implemented by this adapter. Such inputs can be normalized to the import contract with their attribution; uploaded provenance remains unverified.

Forecast fetches now enrich atmospheric records through the Open-Meteo Marine API by default (`include_waves: true`). The fixed endpoint is `https://marine-api.open-meteo.com/v1/marine`, requesting wave height (metres), period (seconds) and direction (degrees). Marine cells must be within 25 km of both the requested point and atmospheric cell. Values merge only at exact UTC timestamps; there is no extrapolation, nearest-time wave replacement or zero fallback. Archive fetches do not automatically request historical marine data.

Datasets retain `wave_source_url`, `wave_grid_latitude`, `wave_grid_longitude`, `wave_fetch_status` and `wave_fetch_detail`. Statuses are complete, partial, unavailable, not_requested or not_applicable. Atmospheric data can still be saved if the marine provider is unavailable, but missing waves remain null and JIT still refuses an incomplete marine recommendation. Normalized record hashes include merged wave values. The marine grid is model output, not a buoy measurement or a navigation guarantee; coverage near shore and in different Caspian cells must be checked individually. Marine API documentation and licensing: https://open-meteo.com/en/docs/marine-weather-api and https://open-meteo.com/en/terms .
